# Implementation decisions

1. **Existing repository:** `/workspace/ada` contained only Git metadata. Implemented the requested default Next.js/React/TypeScript, Supabase and OpenAI stack. No existing code or user data was replaced.
2. **Document scope:** The user's “Implement” authorizes implementing the attached product specification. The document's example first command is treated as a suggested workflow, not an independent user instruction limiting work to slices 0–1. Implemented the local vertical loop through retention/hardening, with verification limits recorded separately.
3. **Aggregate PostgreSQL model:** A learner's drafts, courses, goal/curriculum versions, activities, evidence, reviews, profile and receipts are one JSONB document. CAS enforces transactionality and detects competing writes. This deviates from the suggested normalized schema and has a documented 5 MB/per-learner contention limit. UUID domain identities are server-generated. Course deletion removes the entire dependent subtree. Existing evidence is retained on goal edits.
4. **Private grading data:** Since the aggregate contains teacher-only fields, granting direct learner SELECT would expose answers. RLS is enabled and all direct anon/authenticated access is revoked. Reads/writes use a server-only service role after verified `getUser()` authentication and explicit owner scoping. Only the server role can execute CAS. Self-account deletion is a separate authenticated `auth.uid()` function.
5. **Compact API:** Authenticated versioned JSON command endpoint plus state/export/auth endpoints instead of the spec's suggested per-entity REST route set. The domain service, schema and learner DTO are separate from rendering. All current-activity mutations carry the expected activity ID; saved answers additionally use optimistic versions. CAS protects concurrent transitions.
6. **Local development mode:** Explicit `ADA_DEV_AUTH=true` enables one file-backed fixture learner. Explicit `MOCK_MODEL=true` enables generic deterministic questions visibly labeled as fake. Both are refused in production. The mock deliberately avoids topic-specific lessons so it cannot be confused with successful generation. No default demo courses are inserted.
7. **AI adapter:** Server-only OpenAI SDK with strict structured JSON/Zod, bounded repairs, SDK retries and timeout/output ceilings. No search or source retrieval; no generated bibliography. React renders content as text, never arbitrary Markdown HTML. No model-generated code runs anywhere.
8. **Session simplification:** Each course has one resumable activity checkpoint and append-only activity/evidence history. This implements pause/resume but not normalized, independently addressable historical session entities. No fake completion credit for reading/reflection.
9. **Mastery and recall:** Distinct question text, independence and difficulty determine proficiency, not merely different activity UUIDs. Assisted attempts cannot establish independent demonstration. Review due reflects a scheduled recall, not proof of forgotten skill. Existing evidence survives a changed goal. Goal-merged graphs are validated before persistence.
10. **Minimal UI:** White workspace, quiet purple accent, fixed course sidebar, one prompt and one current activity, understated tabs. No populated sample course catalog or chat sidebar. Plain-text safe rendering; system font fallback avoids remote font dependencies.
11. **Verification:** Unit/domain tests and HTTP journey tests run locally with fixtures. Browser tests are authored but gated, because this managed environment offers no supported browser-control tools. No browser installation or screenshot is represented as completed. No Supabase/OpenAI credentials were configured, so real-provider tests and SQL/RLS execution remain explicitly unverified.
12. **Build compatibility:** Installed Next.js 16.4.5 defaults to CLI type checking. Its CLI-output parser failed here despite standalone `tsc` succeeding. Enabled the documented `experimental.useTypeScriptCli=false` compiler API path; the production build then passed. Type checking remains enabled, separately and in the build.
13. **Hosting:** Deliver runnable Node source rather than publishing a partially configured live application. The requested default stack is Node-compatible, whereas the available Sites host targets Cloudflare Workers; no unnecessary worker port or unconfigured public deployment was added.
14. **Deferred:** Notification sending, retrieval, branch editing, concept-targeted study, graph visualization, telemetry pipeline, sandboxed coding and monetary usage accounting. Reminders are always off; settings state this rather than presenting a dummy delivery toggle.
